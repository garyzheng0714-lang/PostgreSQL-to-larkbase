# Feishu Data Connector Platform — Design Document

Generated by CEO Plan Review on 2026-03-18

## Vision

从一个点对点的 PostgreSQL→飞书多维表格同步工具，进化为 **飞书数据连接平台**：任意数据源（PostgreSQL、MySQL、MongoDB、REST API）同步到飞书 Bitable，支持增量更新、实时监控，可选 SaaS 托管。

### Platonic Ideal

一个业务分析师在飞书多维表格里点击"添加数据源"，选择 PostgreSQL，填入凭证。3 秒后看到所有表和行数。勾选 3 张表，实时预览字段类型映射，点击"同步"。进度条推进 30 秒，数据就位。第二天只有变更的行被增量同步——她甚至不知道这在发生。如果同步失败，一条飞书消息告诉她哪里出了问题。

### Adapter Protocol

```python
class DataSourceAdapter(Protocol):
    async def test_connection(config: dict) -> ConnectionResult
    async def list_databases(config: dict) -> list[str]
    async def list_tables(config: dict, database: str) -> list[TableInfo]
    async def list_columns(config: dict, table: str) -> list[ColumnInfo]
    async def fetch_records(config: dict, table: str, offset: int, limit: int) -> RecordBatch
    async def get_primary_key(config: dict, table: str) -> str | None
    async def supports_incremental(config: dict) -> bool
    async def fetch_incremental(config: dict, table: str, since: datetime) -> RecordBatch
```

每个数据源一个完整模块：`adapters/postgres/`、`adapters/mysql/` 等，各自包含 service、type_mapper、formatter。

设计原则："表"是任意数据集，不局限于关系型的行/列。REST API 的"表"可以是一个 JSON endpoint 的扁平化结果。

### 元数据存储

使用服务器已有的 PostgreSQL（112.124.103.65:5433）存储：
- 同步历史（时间戳、行数、耗时、状态）
- 连接器配置元数据
- 告警规则

## Phased Rollout

### Phase 1: Foundation + Delight

| 工作项 | 描述 |
|--------|------|
| Adapter 抽象层 | DataSourceAdapter Protocol + adapter registry |
| PG Adapter 重构 | 从 pg_service.py 重构为完整 adapter 模块 |
| 统一错误处理 | 所有飞书端点返回协议格式错误，结构化日志 |
| 连接池 | 每个 adapter 管理自己的连接池 |
| SQL 安全加固 | EXPLAIN 验证层 + 保留只读事务双重保障 |
| 管理后台 | 同步历史、健康仪表盘、请求追踪 |
| 飞书机器人告警 | 同步失败时发送飞书消息 |
| 集成测试 | Docker Compose PG 实例，每个 adapter 对称测试 |
| Delight UX | PG 版本显示、字段预览、进度反馈、SQL 高亮、配置导出、行数估算、暗色主题 |

### Phase 2: Multi-Source + Incremental

| 工作项 | 描述 |
|--------|------|
| MySQL Adapter | 完整 adapter 模块 + 集成测试 |
| MongoDB Adapter | 完整 adapter 模块 + 集成测试 |
| REST API Adapter | JSON endpoint → 表的适配 |
| 增量同步 | 时间戳/CDC 智能同步 |
| 快照事务 | REPEATABLE READ 保证分页一致性 |
| 零停机部署 | Docker Compose 滚动更新 |

### Phase 3: SaaS

| 工作项 | 描述 |
|--------|------|
| 飞书 OAuth | 用户认证 |
| 多租户隔离 | 每用户配置隔离 |
| 凭证加密 | 数据库密码加密存储 |
| 计费系统 | 使用量计量 + 配额 |

## Decisions Log

| # | 决策 | 选择 | 原因 |
|---|------|------|------|
| 1 | Adapter 层厚度 | 每个数据源完整模块 | 独立开发测试，强隔离 |
| 2 | 元数据存储 | 已有 PostgreSQL | 复用设施，SaaS 就绪 |
| 3 | SQL 安全 | EXPLAIN 验证 + 只读事务 | 双重保障优于黑名单 |
| 4 | 连接池 | 每 adapter 独立池 | 资源隔离，并发安全 |
| 5 | 告警通道 | 飞书机器人 | 用户已在飞书生态，最低摩擦 |
| 6 | 分页一致性 | Phase 2 快照事务 | 当前全量模式风险可接受 |
| 7 | 零停机部署 | Phase 2 | 当前用户量低，风险可接受 |
| 8 | REST API "表"概念 | 任意数据集 | 接口不绑定关系型假设 |

## Not In Scope

- 双向同步（飞书→数据源回写）— 冲突解决极复杂，协议未必支持
- Kafka/消息队列集成 — 超出连接器定位
- 自定义 ETL 转换 — 属于数据工程平台
- 多区域部署 — Phase 3 之后考虑
